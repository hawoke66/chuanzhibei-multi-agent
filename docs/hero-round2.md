## 7 个点逐条

1. **纵向构图 / 死区 / 任务栏被切**
   去掉 `min-h-dvh` 的拉伸，改成「内边距 + 内容」定高：桌面 `pt-24 / pb-24`，首屏 557px，任务输入面板从 477px 开始、到 881px 结束，**整块落在 900px 视口内**（下沿离底 19px），提交按钮完整可见，不再只露半截。
   内容与面板之间的净空 16px（面板自带的 `-mt-20` 吃掉 80px 内边距），标题 → 链路 → 任务栏三者节奏由 24 / 32 / 16 拉开。
   移动端反过来处理：首屏 `min-h-dvh` 且内容居中，面板起点被推到 876px（折叠线 844px 之下），首屏不出现被切的面板。

2. **协作链路 SVG**
   链路图改成「HTML 节点 + SVG 连线」：节点用与专家区同一套四角星状态点（调度官 20px 完成态、调研员 16px 进行中、文案官/代码手 16px 等待、质检官 20px 等待），尺寸比上轮放大（上轮中间三点是 6px 圆点，现在是 16px 星点），名字用 12px 正文字体而不是 SVG 缩放文字。
   连线分两级：调度 → 三位专家是 `ink-2 / 46%` 实线（已派活），三位专家 → 质检是 `ink-3 / 26%` 虚线（未走到）；两端各留 26 单位空隙，线不压星点。
   链路与标题区同为 6 栏、垂直居中对齐（标题块 96–441px，链路 103–461px），重心不再一边轻一边重。

3. **两个小标签**
   「协作链路」与「4 位专家 · 3 个阶段」统一为 Caption（12 / 16 medium，`ink-2`），同一基线、同一条 hairline，分别钉在链路栏的左右两端，不再一个 12px 一个 mono 12px 的混用，也不再偏暗。

4. **标题与副标题**
   桌面仍为 Heading 2（48 / 48，两行，680px 内断在「让小团队 / 低成本拥有一个 AI 团队」）。副标题 `16 / 28`（两行 56px，行距 28px 落在 4px 网格上）。

5. **按钮区**
   主按钮 8/16 内边距、次按钮纯文字链接，间距 16px；都加 `whitespace-nowrap` 防换行；焦点环 `outline-2 / offset-2 / accent`、hover 变色、active 下移 1px 均在。实测点击「开始派任务」：`scrollY = 229`，`document.activeElement = #task-input`，滚动到位后输入框拿到焦点。

6. **小行星与星云**
   小行星重画（暗面 + 边缘光 + 内侧高光 + 两个坑），落在 `x = 3.2r`、`y = 0.86 × 视口高` 的左下空档，任务栏左缘之外，900px 视口下完整可见（760–788px），不再被面板裁掉；窄屏（< 768px）不画，避免挤在首屏。

7. **390px 首屏**
   链路图只留节点与连线（名字 `sm` 以下隐藏）；标题 30 / 36（桌面 48 → 平板 36 → 手机 30，逐档取 token）；两个按钮并排不换行、不溢出（实测 `scrollWidth = 390`，无横向滚动）；首屏铺满一屏，面板在折叠线之下。

## 拿不准、等验收定

1. **手机标题用 30px（Heading 4）而不是 24px（Heading 5）**：24px 会低于下方区块标题（36px），层级倒挂；30px 是 48 的下一档，也仍在一行内放得下。要更小我再降一档。
2. **链路容器从 8:5 压到 2:1**：要让任务栏整块进首屏，链路高度只能取 312px；宽度和节点都放大了，但纵向比上轮扁。如果更看重链路的纵向伸展，可以接受任务栏下沿被切 20px 左右。
3. **链路示意的是「调度完成、调研进行中、另外两位等待」这一帧**：首屏图不接实时状态（不能碰 `page.tsx`），只是流程图的一个瞬间；如果你希望它永远显示全等待，我把三颗星都改成空心。
4. **小行星的位置**：现在是视口左下、任务栏左侧的留白里。若嫌它离面板太近，可以再往下压到面板下沿之外（会落到首屏之外，需要滚动才看见）。
